## 分层职责

| 层 | 职责 | 核心组件 | 技术栈 |
|----|------|----------|--------|
| **数据层** | 多源数据采集、清洗、存储 | 爬虫管理器、数据管道 | httpx, Selenium, BS4 |
| **模型层** | VLM 视觉理解、特征工程、溢价回归 | VLM Pipeline、Feature Store、XGBoost | InternVL2, Qwen2-VL, scikit-learn |
| **智能体层** | 多 Agent 协作、任务调度、LLM 报告 | Orchestrator、Collector、Analyzer、Reporter | LangGraph, GPT-4o-mini |
| **展示层** | Web 交互、可视化、报告导出 | Streamlit Dashboard | Streamlit, Plotly, ECharts |

## 数据流

```
用户输入 (英雄/皮肤/游戏) 
    → Collector Agent (多源数据采集)
    → VLM Pipeline (皮肤图片视觉分析)
    → Feature Pipeline (31维特征向量构建)
    → Ensemble Predictor (规则引擎 + XGBoost)
    → Business Analyzer (定价/风险/竞品)
    → Report Generator (LLM 自然语言报告)
    → 前端渲染 (雷达图/指标卡/报告文本)
```

## 核心设计原则

1. **冷启动友好**：规则引擎保证 0 数据时可用，随数据积累逐步切换到 ML
2. **可解释性**：五维度分解 + 特征重要性分析，每个溢价分数都可追溯
3. **模块解耦**：每个模块独立可测试，通过特征存储交换数据
4. **渐进式架构**：SQLite → PostgreSQL，规则引擎 → XGBoost，单进程 → 微服务
5. **中文原生**：VLM 选型、Prompt 设计、报告输出均以中文为第一语言

## 技术选型理由

### 为什么选择 InternVL2 + Qwen2-VL 而非 GPT-4V？

| 维度 | 开源 VLM | GPT-4V API |
|------|----------|------------|
| 数据隐私 | ✅ 本地处理，图片不出境 | ❌ 上传至 OpenAI |
| 成本 | ✅ 一次部署，无限调用 | ❌ ~$0.01/张，900 张 ≈ $9/次 |
| 延迟 | ✅ 批量推理 ~0.5-2s | ❌ API 网络延迟 ~2-5s |
| 游戏 UI 理解 | ✅ 可微调 | ⚠️ 通用模型，需要 prompt 调优 |
| 中文支持 | ✅ 原生中文训练 | ⚠️ 中文能力次于英文 |

### 为什么选择 LangGraph 而非 CrewAI/AutoGen？

| 维度 | LangGraph | CrewAI | AutoGen |
|------|-----------|--------|---------|
| 状态管理 | ✅ 内置 TypedDict State | ⚠️ 依赖共享内存 | ⚠️ 依赖消息传递 |
| 工作流控制 | ✅ 图结构 + 条件边 | ❌ 线性/顺序执行 | ⚠️ 订阅模式 |
| 错误恢复 | ✅ 条件路由 + 重试 | ❌ 基础异常处理 | ⚠️ 需要手动实现 |
| 可观测性 | ✅ LangSmith 集成 | ❌ 有限 | ⚠️ 有限 |
| 生态兼容 | ✅ LangChain 生态 | ❌ 独立生态 | ❌ 微软生态 |
