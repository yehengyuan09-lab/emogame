### Llama3.2-Vision:11b Cross-Test

Tested `llama3.2-vision:11b` with the Chinese `L2_PROMPT`:

| Metric | `qwen2.5vl:3b` | `llama3.2-vision:11b` |
|--------|----------------|----------------------|
| Latency | 1.9s | 20.6s |
| Output format | Clean JSON | Markdown prose |
| `parsed_json` | ✅ Valid L2Output | ❌ None (parse failed) |
| Language | Chinese (matches prompt) | English (ignores prompt language) |

**Conclusion:** Switching L2 to `llama3.2-vision:11b` requires an English-translated `L2_PROMPT` and higher `num_predict` (output was truncated at 700 tokens). Without these changes, every L2 call via llama3.2-vision would fail validation and route to fallback.

## Issues Found

### 🔴 Critical
- **`vlm/config.py:20` — L2 model is `qwen2.5vl:3b`, should be `llama3.2-vision:11b`** per design doc. Pipeline currently runs L1 and L2 on the same model.

### 🟡 Quality
- **L1 prompt: `rarity_tier` returns literal options string** `"勇者|史诗|传说|无双|荣耀典藏"` instead of picking one. Prompt needs to be more directive.
- **L1 prompt: `dominant_colors` returns generic placeholders** `#000000, #FFFFFF, #FF0000, #00FF00, #0000FF` — model didn't actually analyze image colors.
- **`llama3.2-vision:11b` incompatible with Chinese L2 prompt** — returns prose, not JSON. Needs English prompt + higher token limit before L2 can switch models.
- **L3 client doesn't bypass SOCKS proxy** — `AsyncOpenAI()` in `l3_semantic.py` lacks `trust_env=False`. Crashes when `all_proxy` is set and `socksio` not installed. OllamaClient handles this correctly.
